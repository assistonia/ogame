## 해석

LLM은 매 판단마다 그럴듯한 병목(에너지 적자, 크리스탈 부족, 창고 포화)을 정확히 짚었다. 그런데 그 대응으로 엔진 기본값을 덮어쓰면서 오히려 손해를 봤다.

- **방어 과투자**: 최종 정책의 `defense_ratio`가 0.4~1.0(평균 0.71). 고정 정책은 엔진 기본값(오버라이드 없음).
- **함선·미션 축소**: ll02 `max_active_missions` 1, ll05 0, ll06·ll05 재투자 0~0.01. 원정·약탈 기회를 스스로 줄였다.
- **성향 흔들기**: ll03·ll04는 raider로 시작해 16~48턴 안에 hybrid/miner로 바꾸고 이후 계속 오갔다.
- 차이가 가장 큰 곳은 miner 자리(-31%, -40%). 엔진 기본값으로 돌린 고정 miner는 원정·약탈도 활발히 해서(st02 farm 50회) 점수가 높았다.

한 줄 요약: **이 엔진에서는 LLM의 "규칙변경"이 기본 정책보다 나쁘다.** v1에서 보였던 LLM 우위는 클래스 차이(explorer 전환)였다는 기존 평가와도 맞는다.

## 알려진 한계

1. **판 수 1개** (seed 1). 다만 6/8 자리에서 같은 방향이고 miner 차이가 커서 우연만으로 보기 어렵다.
2. **LLM 예산 소진**: 턴 848 이후 LLM 정책 고정. 그 시점 이미 LLM이 뒤처져 있었으므로 결론 방향은 같다.
3. **원정 전투 오류 125건**: 업스트림 `ExpeditionMission`이 Rust 전투 엔진을 하드코딩 → 해적/외계인 조우 시 `Class "FFI" not found`, 다음 처리에서 결과가 다시 굴려짐(원정이 실제보다 안전). 원정 횟수는 그룹 간 비슷해서 비교 편향은 작다. `server/sim.sh` setup에서 수정함(다음 판부터 적용).
4. LLM 호출당 비용이 판 후반으로 갈수록 커졌다($0.027 → $0.075). 프롬프트(제국 스냅샷)가 행성 수와 함께 커지기 때문.
