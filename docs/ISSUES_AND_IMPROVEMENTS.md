## 1. 실행 중 실제로 발생한 문제들 (발생순)

### 인프라
| 문제 | 원인 | 해결 |
|---|---|---|
| git clone 실패 | Xcode 라이선스 미동의 (CLT git 차단) | curl로 tarball 다운로드 우회. 근본 해결은 `sudo xcodebuild -license accept` |
| 도커 마운트 실패 (`operation not permitted`) | colima(도커 VM)가 macOS 보호 폴더 `~/Documents`를 마운트 못함 | 서버 소스를 `~/ogamex`로 이동, 프로젝트 폴더엔 심볼릭 링크. **주의: 이 링크 구조를 모르면 헷갈림** |
| 브라우저 플레이 체감 느림 | ① 개발 모드 = PHP OPcache OFF (주원인) ② colima 파일 마운트 오버헤드 ③ 매분 봇 90 요청 웨이브 | 미해결(선택 과제). OPCACHE_ENABLE=1 재빌드가 정답. 봇 병렬 완화도 보조 수단 |

### 게임 서버 API의 함정
| 문제 | 상세 | 대응 |
|---|---|---|
| **조용한 실패 (가장 중요)** | 건설/건조 요청이 선행조건 미달·자원 부족이어도 HTTP 200 + `{"status":"success"}` 반환하고 큐에 안 들어감. 소형화물선(조선소2+연소엔진2 필요), 식민선 등에서 실제 발생 | 요청 후 `get_levels()`로 실제 반영 확인이 필수. 봇 로직에 "요청→검증" 패턴 내장해야 함 |
| 응답 형식 비일관 | 성공은 `{"status":"success"}`, 실패는 `{"success":false}` — 키 자체가 다름 | `_is_success()` 헬퍼로 두 형태 모두 판정 |
| `/ajax/resources` 500 에러 | 상태 조회용인 줄 알았으나 건물 상세 오버레이용 (파라미터 필수) | overview HTML 파싱으로 대체 (`get_status`) |
| 파라미터명 추측 금지 | 건설 요청 필드가 `type`이 아니라 `technologyId`. CSRF 토큰도 40자 세션 토큰만 유효(32자 더미 존재) | 컨트롤러 소스 확인이 유일한 정답. 모든 ID를 `game_objects.py`에 소스 근거 주석과 함께 고정 |
| 봇용 공식 API 부재 | 레벨/자원 조회가 전부 HTML 파싱 의존 | OGameX 템플릿 바뀌면 깨짐. 개선: 파싱 로직을 한 곳에 모으고 스모크 테스트 스크립트 유지 |

### 봇 운영
| 문제 | 상세 | 대응/개선점 |
|---|---|---|
| 서브에이전트 1개 API 오류로 중단 | 규칙봇 빌더가 작업 도중 연결 끊김 | 파일 상태 확인 후 중단 지점부터 재개 지시로 복구 (재작업 없이) |
| 병렬 상한이 서버에 있음 | 봇 병렬 45→90으로 올려도 바퀴 시간 동일(~24초). PHP-FPM 워커 수가 병목 | 클라이언트 병렬은 45면 충분. 더 원하면 php-fpm 튜닝 |
| 성장이 틱 주기에 묶임 | ×100 배율인데 봇당 1분 1건설이라 레벨 성장이 직선 | 틱당 여러 건 연속 큐잉(자원 소진까지)으로 개선 가능 |
| 검증 계정과 운영 계정 충돌 | 규칙봇 루프가 도는 중에 같은 계정으로 테스트하면 자원을 서로 소모 | 테스트는 뒷번호 계정(bot085~090) 또는 시드 계정으로 분리하는 관례 정착 |
| test2 계정 오염 | 함대 검증 과정에서 test2에 연구+정찰위성이 추가됨 (원복 안 함) | 시드 계정은 검증용으로 쓰고 상태 변화를 기록해두기 (이 문서가 그 기록) |
| bot090 자원 치트 사용 | 함선/식민 검증 가속을 위해 DB로 자원 직접 주입 | 실험엔 유용하나 시뮬레이션 공정성 훼손 — 운영 유니버스에선 금지 규칙 필요 |

### AI 에이전트 (codex/Luna)
| 문제 | 상세 | 개선점 |
|---|---|---|
| 판단 컨텍스트 빈약 | 자원 4종 숫자만 보고 결정 → 사실상 건설 선택기 수준 | 은하 정찰 결과, 함대 이벤트, 순위 정보를 상태 덤프에 포함 |
| 기억 축적 약함 | memory.md 2줄/틱 — 장기 전략 없음 | 구조화된 기억(목표/진행중 계획/적 목록) 포맷 도입 |
| 토큰 사용량 | 틱당 17~18k 토큰. 10명 1바퀴 ≈ 18만 토큰 | 상태를 더 압축하거나, 판단만 API 단발콜로 하고 실행은 스크립트로 분리하는 하이브리드 검토 |
| 원턴 판단의 한계 | "다음 행동 1개"만 결정 → 연속 전략 불가 | 틱에서 행동 여러 개 허용 + 다음 틱 계획을 기억에 남기게 |

## 2. 검증된 성과 (문제만 있던 건 아님)

- 90봇 병렬 안정 가동: 바퀴 24초, 수백 바퀴 무사고, 실패 0
- 30분 ×100 시뮬: 광산 레벨 합 9→1,851, 자원 복리 성장 곡선 재현
- 성격 분화 실증: 채굴러 메탈 7.5 vs 크리스탈러 크리스탈 4.9 (평균 레벨)
- AI 페르소나 실증: 동일 상황에서 레이더/터틀/도박사가 다른 판단 + 말투 유지
- 전투 실증: test2 → bot002 공격, 전투 리포트 생성 (10 전투기, 무저항, 자원 480 약탈)
- 함대 API 전 미션 흐름 규명 (check-target → send-fleet 2단계, am<id> 필드, 미션 타입 1~15)

## 3. 남은 개선 과제 (우선순위순)

1. **봇 로직에 신규 API 반영** — 지금 규칙봇은 여전히 자원건물 4종만 돌림.
   경제→기술→함대→확장 상태머신 + "요청 후 검증" 패턴 필수
2. **식민지 파이프라인 미완** — 천체물리→식민선→빈 슬롯 파견 체인이 중단됨
   (테크트리 스크립트 작성 중 셧다운). 재개 시 bot090이 테크 선행 상태라 이어서 가능
3. **전략 리서치 반영** — `docs/strategies.md` (리서치 진행 중이었음) 기반으로
   성격 5종 가중치·AI 페르소나 지침 개편
4. **AI 입력 강화** — 정찰/이벤트/순위를 판단 컨텍스트로
5. **서버 성능** — OPCACHE_ENABLE=1 재빌드 (브라우저 체감 개선)
6. **운영 자동화** — 봇 루프 launchd 등록, 관전 대시보드(간단한 HTML이면 충분)
7. **플릿세이브 규칙** — 전투 시대가 열리면 봇들이 자원/함대를 지키는 루틴 필요

## 4. 재가동 절차 (셧다운 상태에서)

```bash
colima start
cd ~/ogamex && docker compose up -d          # ~1분 후 http://localhost
cd ~/Code/80_ogame_simulation
./scripts/watchdog.sh                        # 전체 102명: 4분/parallel 6/spread 240초
```

유니버스 루프에는 규칙봇 90, AI 10, Spark 전용 AI `pirate01`, `explorer01`이 모두 포함된다. 경제 배치는
`.economy_batch_accounts`를 ai01 → AI 10개 → 규칙봇 표본 → `*` 순으로 확대한다.

속도 배율(×100)은 DB에 저장되어 있어 재기동해도 유지됨.
