102명 봇(규칙 90 + AI 12)이 로컬 오게임 서버에서 자율 플레이하는 프로젝트의

## 1. 구축된 것

### 서버 (OGameX)
- 오픈소스 오게임 클론(OGameX, Laravel 12)을 colima 도커로 로컬 가동
  - 컨테이너 7개: nginx / PHP앱 / MariaDB / 스케줄러 / 큐워커 / 웹소켓 / phpMyAdmin
  - 게임: http://localhost · DB관리: http://localhost:8080 (root/toor)
- **경제·연구·함대 속도 ×100 배율** (DB settings 테이블)
- 재기동: `colima start && cd ~/ogamex && docker compose up -d`

### 봇 계정 102개
- `bot001~090@bots.local` (규칙봇) + `ai01~10@bots.local` (AI), 비번 전부 `botpass`
- `pirate01@bots.local`(해적) + `explorer01@bots.local`(탐험가)는
  `gpt-5.3-codex-spark` 전용 AI 정책 계정으로 동일한 유니버스 루프에 포함
- 수동 전투용 계정은 `simulation-admin@ogamex.local`(표시명 `Admin`)로 완전 분리.
  `bot001`은 일반 규칙봇이며 Admin 역할이 없다. 전용 Admin은 `@bots.local` 밖이라
  유니버스 루프·성장 스냅샷·동급 비교 표본에 포함되지 않는다
- 은하1에 배치. 2026-07-12부터 AI 주행성은 규칙봇 사이의
  `1:2/6/10/14/18/22/26/30/35/38`에 균등 분산 (`docs/AI_POSITION_LAYOUT.md`)
- 생성 스크립트: `scripts/seed_bots.sh` (재실행 안전)
- 전용 Admin 운영/테스트 전투: `docs/ADMIN_TEST_ACCOUNT.md`

### 봇 클라이언트 (bots/shared/)
- `client.py` — 로그인(CSRF 처리), 자원조회, 건설(자원건물/시설), 연구, 함선 건조, 레벨 조회

### 규칙봇 90명

## 2. 단점 · 한계 (솔직 버전)

### 게임플레이 한계
- **전투가 아직 없음**: 서버는 전투 엔진 완비, 봇은 함대 파견 API가 완성돼야 공격/정찰/식민 가능 (작업 중)
- **식민지 확장 없음**: 전원 행성 1개. 천체물리 연구→식민선→식민 파견 로직 미구현
- **규칙봇 행동이 단조로움**: 자원건물 4종만 순환 건설. 시설/연구/함선은 API만 있고 봇 로직에 미반영
- **성장 속도가 틱 주기에 묶임**: 봇당 1분에 건설 1회라 레벨 합계가 직선 성장. 배율 ×100의 잠재력을 다 못 씀 (틱당 여러 건 큐잉으로 개선 가능)

### 기술적 함정 (개발 시 주의)
- **API가 조용히 실패함 (중요)**: 건설/건조 요청이 선행조건 미달·자원 부족이어도
  `{"status":"success"}`를 반환하고 큐에 안 들어가는 경우가 있음.
  → 요청 후 `get_levels()`로 실제 반영 확인 필수
- **레벨 조회가 HTML 파싱 의존**: OGameX에 봇용 공식 API가 없어서 페이지 HTML을 긁음.
  OGameX 업데이트로 템플릿이 바뀌면 파싱이 깨질 수 있음
- **colima가 ~/Documents를 마운트 못함**: 서버 소스 실체는 `~/ogamex`,
  프로젝트 폴더의 `ogamex`는 심볼릭 링크

### 성능
- **브라우저 플레이가 느림**: ① 개발 모드라 PHP OPcache 꺼짐(주원인) ② colima 파일 마운트 오버헤드 ③ 매분 봇 90 요청 웨이브 때 사람 요청이 밀림
  - 개선: OPCACHE_ENABLE=1로 재빌드(몇 분 중단), 봇 병렬 90→20 완화
- **서버 처리량 병목**: 봇 병렬을 45→90으로 올려도 바퀴 시간 동일(~24초) — PHP 워커 수가 상한. 더 필요하면 php-fpm 튜닝

### AI 에이전트
- **판단이 아직 얕음**: 상태 요약(자원 4종)만 보고 건설 1건 결정. 은하 정찰 정보, 경쟁자 동향 같은 컨텍스트 없음
- **기억이 2줄/틱**: 장기 전략 누적이 약함
- **codex 구독 한도 의존**: 대량/고빈도 틱은 한도 소진. API 전환 시 비용 발생 (Luna $1/$6 per MTok)

### 운영
- **모니터링이 로그/SQL뿐**: 대시보드 없음 (`scripts/universe.log`, `sim_stats.log`, phpMyAdmin)
- **봇 루프가 세션 종속**: 터미널 백그라운드 프로세스라 재부팅하면 수동 재시작 필요 (launchd/cron 미등록)
- 로컬 전용 세팅: 비밀번호 단순, 보안 고려 없음 (외부 공개 금지)
